## 1. 模块定位与架构分层

### 1.1 核心定位

|维度|说明|
|---|---|
|**模块名称**|`MapProxy`（地图服务代理层）|
|**设计原则**|契约先行（对齐 3.7）、策略可插拔、异常统一处理、降级可控|
|**P0 约束**|所有对外输出必须符合 3.7 JSON 结构；限流触发直接返回 `429`，不返回脏缓存|
|**P2 预留**|内部图算法切换能力（通过配置开关无缝替换高德代理）|

### 1.2 架构分层
~~~
com.project.map.proxy
├── controller          # 统一入口 (MapController)
├── strategy            # 策略模式核心
│   ├── MapStrategy     # 核心接口
│   └── impl
│       ├── AmapStrategy        # 高德实现 (P0)
│       └── InternalStrategy    # 内部算法 (P2)
├── dto                 # 请求参数 (Request/DTO)
├── vo                  # 响应视图 (CommonResponse, VO, PageResult)
├── client              # 外部调用 (AmapClient, SignUtil)
├── converter           # 转换层 (RequestConverter, ResponseConverter)
├── cache               # 缓存服务 (RedisTemplate 封装)
├── limiter             # 限流与配额 (RateLimiter, QuotaManager)
└── exception           # 全局异常与错误码 (GlobalExceptionHandler, ErrorCode)
~~~

## 2. 核心数据契约（严格对齐 3.7）

### 2.1 统一响应包装 `CommonResponse`

由 `ResponseBodyAdvice` 自动注入，所有接口强制返回：

~~~json
{
  "success": true,
  "code": "SUCCESS",
  "message": "success",
  "data": { ... },
  "timestamp": "2026-04-29T12:00:00"
}
~~~

### 2.2 核心 VO 定义

#### 🔹 RoutePlanVO（路径规划）

~~~json
{
  "origin": { "lng": 116.48, "lat": 39.99, "name": "起点" },
  "destination": { "lng": 116.40, "lat": 39.90, "name": "终点" },
  "strategy": "shortest_distance",
  "distance": 12580,
  "duration": 2340,
  "path": {
    "type": "LineString",
    "coordinates": [[116.48, 39.99], [116.40, 39.90]]
  },
  "steps": []
}
~~~

> 📌 `steps` 默认为空数组。仅当请求携带 `extensions=all` 时返回详细步骤。

#### 🔹 PoiVO（兴趣点）

~~~json
{
  "poiId": "B000A7BK6G",
  "name": "故宫博物院",
  "type": "110000",
  "typeName": "风景名胜",
  "location": { "lng": 116.39, "lat": 39.91 },
  "address": "...",
  "city": "北京市",
  "distance": null,
  "rating": 4.8,
  "bizExt": { "openingHours": "...", "telephone": "..." }
}
~~~

#### 🔹 PageResult \<T>（分页包装）

 **仅 `POI 搜索` 与 `周边设施` 接口使用**（`tips` 接口返回扁平 `list`，不分页）：

~~~json
{
  "list": [ { ... } ],
  "pageNum": 1,
  "pageSize": 20,
  "total": 156,
  "pages": 8
}
~~~

### 2.3 请求 DTO 关键约束

| 接口                   | 参数                   | 约束说明                                           |
| -------------------- | -------------------- | ---------------------------------------------- |
| `routes/plan/single` | `strategy`           | 仅允许 `shortest_distance` / `shortest_time`，默认前者 |
| `pois/search`        | `keywords`           | 必填，1-50字符                                      |
| `pois/search`        | `pageNum`/`pageSize` | 默认 `1`/`20`，最大 `50`                            |
| `pois/nearby`        | `location`           | **必填**，格式 `"lng,lat"`                          |
| `pois/nearby`        | `types`              | **必填**，设施类型代码                                  |
| `pois/nearby`        | `sortBy`             | 支持 `distance`（默认）/ `rating`                    |
| `pois/tips`          | `keyword`            | 必填，1-30字符                                      |
| `pois/tips`          | `location`/`types`   | 选填，用于地理/类型优先级过滤                                |

## 3. 接口路由与错误码矩阵

### 3.1 路由映射（P0）

|功能|方法|路由路径|策略方法|
|---|---|---|---|
|单目标路径规划|`POST`|`/api/v1/routes/plan/single`|`strategy.planRoute()`|
|POI 关键词搜索|`GET`|`/api/v1/pois/search`|`strategy.searchPoi()`|
|POI 输入提示|`GET`|`/api/v1/pois/tips`|`strategy.getInputTips()`|
|周边设施搜索|`GET`|`/api/v1/pois/nearby`|`strategy.searchNearby()`|
|地址转坐标|`GET`|`/api/v1/geocode`|`strategy.geocode()`|
|坐标转地址|`GET`|`/api/v1/reverse-geocode`|`strategy.reverseGeocode()`|

### 3.2 错误码矩阵（ErrorCode）

所有接口首列兜底 `COMMON_001`。`MAP_301` 严格映射为 `429`。

|错误码|HTTP 状态码|场景说明|触发条件示例|
|---|---|---|---|
|`COMMON_001`|400|请求参数缺失或格式错误|任意接口必填项为空/类型不符|
|`MAP_001`|400|缺少起点坐标|`origin` 为空|
|`MAP_002`|400|缺少终点坐标|`destination` 为空|
|`MAP_003`|400|坐标格式错误或越界|`lat > 90` 或格式非法|
|`MAP_004`|400|搜索半径超出限制 (1-5000)|`radius > 5000`|
|`MAP_005`|400|关键词为空或过长|`keyword` 长度不符|
|`MAP_006`|400|不支持的路径规划策略|`strategy` 非枚举值|
|`MAP_008`|400|分页参数不合法|`pageNum < 1` 或 `pageSize > 50`|
|`MAP_200`|404|起点终点之间无可行路径|高德 `status=1` 但 `paths` 为空|
|`MAP_201`|404|未找到匹配的地点|`pois count = 0`|
|`MAP_202`|404|指定范围内无目标设施|`nearby` 搜索无结果|
|`MAP_203`|404|地址解析失败|地址无法转换为坐标|
|`MAP_300`|500|Key 无效/过期|`INVALID_USER_KEY`|
|`MAP_301`|**429**|日/分调用次数超限|`DAILY_QUERY_OVER_LIMIT` / 限流触发|
|`MAP_305`|500|起终点距离超限|`OVER_DIRECTION_LIMIT`|
|`MAP_502`|500|外部服务超时|`OkHttp Timeout`|
|`MAP_999`|500|系统内部未知错误|`Catch Exception`|

## 4. 核心实现层设计

### 4.1 缓存策略（Redis）

Key 设计已补齐所有过滤维度，防止数据串流。

|数据类型|Redis Key 格式|TTL|说明|
|---|---|---|---|
|路径规划|`map:route:{oLng},{oLat};{dLng},{dLat};{strategy};{extensions}`|1h|区分基础/详细步骤|
|POI 搜索|`map:poi:{keywords};{types};{city};{pn};{ps}`|24h|热门搜索缓存|
|输入提示|`map:tips:{keyword};{city};{location};{types}`|12h|含位置/类型维度隔离|
|周边设施|`map:nearby:{location};{types};{radius};{sortBy};{pn};{ps}`|1h|按排序与半径隔离|
|逆地理|`map:regeo:{lng},{lat}`|7d|坐标转地址长期缓存|

### 4.2 限流配置
~~~yaml
map:
  rate-limit:
    route: 10          # 10 次/分钟/用户
    poi-search: 30     # 30 次/分钟/用户
    input-tips: 60     # 60 次/分钟/用户
    nearby: 30         # 30 次/分钟/用户
  fallback-enabled: false  # P0 严格模式：超限直接拒绝，不返回旧缓存
~~~
> ⚠️ 触发限流时，HTTP 状态码返回 `429 Too Many Requests`，响应体携带 `MAP_301`。

## 6. 关键注意事项

1. **GeoJSON 转换**：高德返回的 `polyline` 为 `lng,lat;lng,lat` 字符串，必须通过 `ResponseConverter` 拆分为 `double[][]` 并包装为 `{ "type": "LineString", "coordinates": [...] }`。
2. **`bizExt` 透传**：POI 返回的 `bizExt` 为动态扩展信息（营业时间、电话等），必须保留为 `Map<String, Object>` 或透传 JSON，禁止丢弃。
3. **坐标强校验**：所有进入 Controller 的 `lng` `(-180~180)` 和 `lat` `(-90~90)` 必须加 `@Valid` 拦截，非法值直接返回 `COMMON_001`。
4. **分页强制化**：`/pois/search` 与 `/pois/nearby` 的 `data` **必须**包裹在 `PageResult` 中；`/pois/tips` 返回 `{ "list": [...] }` 即可。
5. **策略工厂扩展**：`MapStrategyFactory` 默认返回 `AmapStrategy`，需预留 `@ConditionalOnProperty(name="map.provider", havingValue="internal")` 供 P2 切换。
6. **限流规范**：触发限流时 **严禁** 静默返回旧缓存（`fallback-enabled: false`），前端需捕获 `429` 并提示“请求过于频繁”。
