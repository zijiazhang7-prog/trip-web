# 地图代理模块（MapProxy）代码编写方案 - 5.3 修正对齐版

> 📌 **版本说明**：本文档在 `5.2` 基础上，严格对齐 `3.7（API契约）` 与 `4.5（内部设计）`。已修正路由路径、分页结构、DTO类型、限流HTTP状态码、P0缓存范围等关键偏差。可直接作为 P0 阶段代码生成与开发基线。

---

## 1. 总体架构设计

### 1.1 设计原则

|原则|说明|
|---|---|
|**契约先行**|所有输入输出严格对齐 `3.7` 的 JSON 结构，禁止私自扩展或删减字段|
|**策略隔离**|通过 `MapStrategy` 接口隔离高德代理与未来内部图算法|
|**降级可控**|P0 阶段限流默认严格拦截（`fallback-enabled: false`），不返回脏缓存|
|**零硬编码**|Key/Secret 仅通过环境变量或加密配置注入，严禁写死在代码中|

### 1.2 模块分层（对齐 4.5）

~~~
com.project.map.proxy
├── controller      # REST 接口入口 (MapController)
├── strategy        # 策略模式核心 (MapStrategy, impl/AmapStrategy)
├── dto             # 请求参数对象 (RoutePlanRequest, PoiSearchRequest...)
├── vo              # 响应视图对象 (RoutePlanVO, PoiVO, PageResult, CommonResponse)
├── converter       # 转换层 (RequestConverter, ResponseConverter) 专责 GeoJSON/DTO映射
├── client          # 高德 HTTP 客户端 (AmapClient, SignUtil)
├── cache           # 缓存服务 (RedisCacheManager)
├── limiter         # 限流切面 (RateLimiterAspect, RedisSlidingWindow)
├── config          # 配置类 (MapProperties, MapConfig)
├── enums           # 枚举定义 (StrategyEnum, ErrorCode)
├── exception       # 异常处理 (MapApiException, GlobalExceptionHandler)
└── advice          # 响应增强 (ResponseBodyAdvice 注入 timestamp)
~~~

## 2. 详细实施步骤

### 阶段一：基础设施与配置 (P0-Step1)

**目标**：搭建骨架，安全加载 Key，打通 HTTP 通道，配置限流与降级策略。

1. **依赖管理 (`pom.xml`)**
    - `okhttp3` (HTTP 请求)
    - `jackson-databind` (JSON 序列化)
    - `lombok` (简化样板代码)
    - `spring-boot-starter-web`, `spring-boot-starter-data-redis`, `spring-boot-starter-aop`
2. **配置类 (`config/MapProperties`)**

~~~yaml
map:
  provider: amap
  amap:
    api-key: ${AMAP_API_KEY}
    secret: ${AMAP_SECRET}
    timeout: 5000
    retry-count: 1
  rate-limit:
    route: 10        # 次/分钟
    poi-search: 30
    input-tips: 60
    nearby: 30
  fallback-enabled: false  # P0 严格模式：超限直接拒绝
~~~
    
    - 启动时校验 `apiKey` 与 `secret` 非空，否则阻断应用启动。
3. **HTTP 客户端 (`client/AmapHttpClient`)**
    - 基于 OkHttp 封装单例，统一注入签名、处理超时/重试。
    - `SignUtil` 实现高德 SHA1 签名逻辑。
4. **错误码枚举 (`enums/ErrorCode`)**
    - 定义 `MAP_001` ~ `MAP_999` 及对应 HTTP 状态码。**注意**：`MAP_301` 必须映射为 `HttpStatus.TOO_MANY_REQUESTS (429)`。

### 阶段二：领域模型定义 (P0-Step2)

**目标**：统一输入输出格式，严格对齐 3.7 契约。

1. **通用响应 (`vo/CommonResponse<T>`)**
~~~
public class CommonResponse<T> {
    private boolean success;
    private String code;
    private String message;
    private T data;
    private String timestamp; // 由 ResponseBodyAdvice 自动注入
}
~~~ 
2. **分页包装 (`vo/PageResult<T>`)**
    
    > ⚠️ 仅用于 `search` 与 `nearby` 接口。`tips` 接口仅返回 `{ "list": [...] }`。
~~~java
public class PageResult<T> {
    private List<T> list;
    private int pageNum;
    private int pageSize;
    private long total;
    private int pages;
}
~~~
    
3. **请求 DTO (`dto/`)**
    - `RoutePlanRequest`: `strategy` 类型为 **`String`**（默认 `"shortest_distance"`），支持 `extensions` 参数。
    - `PoiSearchRequest`: 使用 `pageNum`/`pageSize`（废弃 `page`），`keywords` 长度 1-50。
    - `PoiNearbyRequest`: `location` 与 `types` 标注 `@NotBlank`；支持 `sortBy`（`distance`/`rating`）。
    - `GeoCodeRequest` / `ReverseGeoCodeRequest`: 坐标范围校验 `@Range`。

### 阶段三：核心策略实现 (P0-Step3)

**目标**：实现 `AmapStrategy`，完成业务逻辑编排与数据转换。

1. **策略接口 (`strategy/MapStrategy`)**
~~~java
RoutePlanVO planRoute(RoutePlanRequest req);
PageResult<PoiVO> searchPoi(PoiSearchRequest req);
TipsResultVO getInputTips(PoiTipsRequest req); // TipsResultVO 仅包含 List<PoiVO> list;
PageResult<PoiVO> searchNearby(PoiNearbyRequest req);
GeoCodeVO geocode(GeoCodeRequest req);
ReverseGeoCodeVO reverseGeocode(ReverseGeoCodeRequest req);
~~~
2. **高德策略实现 (`strategy/impl/AmapStrategy`)**
    - **路径规划**：解析 `/v3/direction/driving`，提取 `distance`/`duration`。若 `extensions=all`，解析 `steps` 明细；否则返回空数组。
    - **POI 搜索/周边**：调用对应 API，映射字段至 `PoiVO`，`bizExt` 原样透传为 `Map<String, Object>`。
    - 错误映射：捕获高德 status=0 抛业务异常；**若 status=1 但 paths/roads 数组为空或 length=0，手动抛出 MAP_200(404)**；其他限流/超限错误按 info 映射至对应 ErrorCode。
3. **工厂类 (`config/MapStrategyFactory`)**
    - 根据 `map.provider` 返回实例，默认注入 `AmapStrategy`。预留 `@ConditionalOnProperty` 供 P2 切换。

### 阶段四：控制器与异常处理 (P0-Step4)

**目标**：暴露 REST 接口，统一错误响应，拦截限流。

1. **控制器路由 (`controller/MapController`)**
    
    > ✅ 路径必须与 3.7 完全一致，禁止省略 `/api/v1/` 前缀。
~~~java
@PostMapping("/api/v1/routes/plan/single")
@GetMapping("/api/v1/pois/search")
@GetMapping("/api/v1/pois/tips")
@GetMapping("/api/v1/pois/nearby")
@GetMapping("/api/v1/geocode")
@GetMapping("/api/v1/reverse-geocode")
~~~
    
2. **全局异常处理 (`exception/GlobalExceptionHandler`)**
    - `MapApiException` -> 返回对应 `ErrorCode` 与 HTTP 状态码。
    - `MethodArgumentNotValidException` / `ConstraintViolationException` -> 统一返回 `COMMON_001` (400)。
    - `RateLimitExceededException` -> 强制返回 `429 Too Many Requests` + `MAP_301`。
3. **响应增强 (`advice/TimestampAdvice`)**
    - 实现 `ResponseBodyAdvice`，拦截所有 `CommonResponse`，自动填充 `timestamp = Instant.now().toString()`。

### 阶段五：缓存与限流落地 (P0 必须实现)

**目标**：P0 阶段直接接入 Redis 缓存与滑动窗口限流，禁止占位注释。

1. **缓存服务 (`cache/RedisCacheManager`)**
    - Key 生成严格遵循 4.5 维度隔离规范（例：`map:route:{oLng},{oLat};{dLng},{dLat};{strategy};{extensions}`）。
    - TTL 配置：路径 `1h`，POI搜索 `24h`，Tips `12h`，周边设施(nearby) 1h，逆地理 `7d`。
2. **限流切面 (`limiter/RateLimiterAspect`)**
    - 基于 Redis `Lua` 脚本实现滑动窗口计数。
    - 拦截 Controller 方法前校验配额，超限抛 `RateLimitExceededException`。
    - 若 `fallback-enabled: true`（P0 关闭），返回缓存；若 `false`，直接阻断。

## 3. 关键逻辑细节规范

### 3.1 签名与安全

- 签名必须在 `AmapHttpClient` 发送请求前计算，格式：`params + "&key=" + apiKey + "&sig=" + sha1(params + "&key=" + apiKey + secret)`
- 日志打印参数时，`location` 保留小数点后 4 位，敏感字段脱敏。

### 3.2 坐标系与几何转换

- 输入校验：`lng` `[-180, 180]`，`lat` `[-90, 90]`，非法值由 `@Valid` 拦截返回 `COMMON_001`。
- **GeoJSON 转换**：高德 `polyline` 为 `lng,lat;lng,lat` 字符串，必须通过 `ResponseConverter` 拆分为 `double[][]`，包装为：
~~~json
{ "type": "LineString", "coordinates": [[lng,lat], [lng,lat], ...] }
~~~

### 3.3 错误码与 HTTP 状态映射

|业务场景|错误码|HTTP 状态码|处理方式|
|---|---|---|---|
|参数校验失败|`COMMON_001`|400|`GlobalExceptionHandler` 统一捕获|
|路径不可达|`MAP_200`|404|策略层解析后抛出|
|日/分调用超限|`MAP_301`|**429**|限流切面拦截，严禁返回 400/500|
|外部服务超时|`MAP_502`|500|HTTP Client 超时捕获|
