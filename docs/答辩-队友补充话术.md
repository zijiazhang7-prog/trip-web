## A. RankService（公共组件，优先背）

| 项目 | 内容 |
|------|------|
| 结构 | 小顶堆 `PriorityQueue`，维护当前「最差」的 K 个 |
| 用法 | 目的地推荐、美食推荐、日记推荐、设施/搜索后排序 |
| 复杂度 | O(n log k)，k 通常 10 |
| **插话句** | 「推荐类功能统一走 RankService，避免全量 sort，符合课设只取 Top10 的要求。」 |

## C. 路线规划（图 + 最短路）

**代码**：`MapServiceImpl.java` → `GraphEngine.java`、`EdgeCostCalculator.java`

### 图建模

- **节点**：`map_node`（建筑/场所/设施锚点）  
- **边**：`map_edge` 有向带权（distance、ideal_speed、crowd_factor、transport_type）  
- **结构**：邻接表 `Map<nodeId, List<GraphEdge>>`  

### 单源最短路 — Dijkstra

| 策略 | 边权 |
|------|------|
| 最短距离 | `distance` |
| 最短时间 | `distance / (min(工具速度, ideal_speed) × crowd_factor)` |

- 工具默认速度：walk 80、bike 250、cart 300（m/min 量级）  
- **mixed**：状态 `(nodeId, transportType)`，节点可换乘；边权限 `EdgeTransportAccess`（walk / bike / cart / walk_bike / walk_cart / all 等）  
- 复杂度：单工具 O((V+E)logV)；混合约 O((TV+TE)log(TV))  

### 多目标 — 最近邻启发式

1. 当前点跑 Dijkstra → 未访问目标中最短者  
2. 拼接该段路径，移到该点，重复  
3. 可选 `returnToStart` 回起点  
4. **不保证 TSP 全局最优** · 复杂度 O(k(V+E)logV)  

**接口**：`POST /routes/plan/single`、`POST /routes/plan/multi`

**插话句**：「景区内部是有向带权图 Dijkstra；多景点是最近邻启发式；时间策略把拥挤度乘进有效速度。」

**前端**：校园显示步行/骑行/混合；景区显示步行/电瓶车/混合（`internalTransport.ts`）。

## D. 周边设施（图距离，非直线）

**代码**：`FacilityServiceImpl.java`

```
按 facilityType SQL 过滤候选
  → facility.ref_id 映射 map_node
  → 一次 shortestDistances(sourceNodeId) 单源 Dijkstra
  → 各设施取 reachableDistance，过滤 radius
  → 按可达距离升序排序分页
```

- 复杂度：一次 Dijkstra + O(m log m)  
- **接口**：`GET /facilities/nearby`  

**插话句**：「附近设施只跑一遍最短路，按图上可达距离排序，课设要求不用直线距离。」

**前端**：合并在 `NavigatePage` 附近设施侧栏。

## 架构分层（助教问「算法放哪」）

```
Controller → Service（编排/事务/鉴权）→ Engine（纯算法）→ Mapper（DB）
```

Engine 层：**GraphEngine、IndexEngine、CompressionEngine、RankService** — 不依赖 Entity/Mapper。

**插话句**：「算法和业务解耦，Engine 只接受图、文档、候选列表，方便单测和答辩讲清楚复杂度。」

---

## 性能一问通答

> 「候选集有上限（如日记 200 篇），推荐用 Top-K 堆 O(n log k)；设施附近只跑**一次**单源最短路，不对每个设施重复 Dijkstra；索引内存快照读无锁，写入原子替换。」
